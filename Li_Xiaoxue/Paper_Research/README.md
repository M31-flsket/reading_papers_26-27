## 1. 研究方向确认

### 1.1 当前确定的课题

**星载遥测数据智能异常检测与边缘部署**

英文方向表述：

*Intelligent Anomaly Detection for Spacecraft Telemetry and Edge Deployment*

当前研究主线：

**航天器遥测数据 → 时序异常检测算法 → 算法改进 → Linux 嵌入式部署 → 硬件性能验证**

本方向结合软件工程专业背景、Linux/嵌入式系统学习基础，以及对硬件实验的偏好，重点研究计算机技术在航天器状态监测与健康管理中的应用。

### 1.2 研究对象

航天器在运行过程中会持续产生遥测数据，例如：

- 电源系统：电压、电流等参数；
- 热控系统：温度等参数；
- 姿态控制系统：姿态及相关运行参数；
- 通信系统：通信链路及设备状态参数；
- 星载计算机：CPU、内存及设备运行状态。

这些数据通常具有时间序列和多变量特征。研究目标是从遥测数据中识别偏离正常运行状态的异常模式，为航天器状态监测和故障预警提供支持。

### 1.3 当前研究定位

现阶段定位为：

- **应用领域：** 航天器状态监测、健康管理；
- **研究对象：** 航天器多变量遥测时间序列；
- **核心技术：** 时间序列分析、机器学习、深度学习、异常检测；
- **系统技术：** Linux、嵌入式系统、边缘计算、模型部署；
- **实验方式：** 公开数据集算法实验 + Linux 嵌入式平台部署与测试。

当前优先使用公开数据集和地面嵌入式平台开展研究。开发板上的实验属于地面原型验证，不能表述为真实卫星在轨验证。

## 2. 研究目标与拟解决的问题

### 2.1 总体研究目标

面向航天器遥测数据，研究在多变量关联复杂、异常样本有限、嵌入式计算资源受限等条件下，如何实现准确、可靠且计算开销可控的异常检测，并在 Linux 边缘计算平台上完成部署和性能验证。

### 2.2 拟研究的核心问题

以下是当前的候选研究问题。需要通过文献阅读、基线复现和实验分析进一步确定最终主问题，不预先认定它们就是创新点。

#### 问题一：如何有效利用多变量遥测数据之间的关联关系？

单个遥测通道可能没有明显异常，但多个通道之间的关联关系可能已经发生变化。

拟关注的内容：

- 多变量时间序列特征提取；
- 时间依赖关系建模；
- 遥测变量之间的相关性或依赖关系建模；
- 时间特征与变量关联特征融合；
- 异常评分与异常判定。

#### 问题二：异常样本有限时，如何实现有效检测？

实际航天器异常事件相对少见，异常数据可能存在类别不平衡、标注不完整等问题。

拟关注的内容：

- 无监督异常检测；
- 半监督异常检测；
- 基于正常数据训练的异常检测；
- 小样本或异常样本稀缺场景；
- 不同异常类型下的泛化能力。

#### 问题三：如何让异常检测模型适应资源受限的嵌入式平台？

在 PC 上具有较好检测效果的模型，不一定能够在嵌入式设备上实时、稳定运行。

拟关注的内容：

- 轻量化模型结构；
- 模型剪枝、量化和知识蒸馏；
- 推理延迟与内存占用优化；
- CPU/GPU 资源使用情况；
- 检测性能与计算开销之间的权衡。

### 2.3 当前研究问题的优先顺序

1. 先理解航天器遥测数据及其异常检测任务；
2. 复现传统机器学习和深度学习基线；
3. 根据实验结果确定一个主要问题；
4. 围绕主要问题设计改进方法；
5. 在 Linux 嵌入式平台上验证模型运行性能。

## 5. 文献阅读顺序与方法

### 5.1 推荐阅读顺序

建议按照以下顺序建立知识体系：

1. **先读航天器遥测与健康管理：** 搞清楚研究对象和应用需求；
2. **再读时间序列异常检测：** 掌握异常检测的基本方法；
3. **接着读多变量时序建模：** 寻找可能的算法研究切入点；
4. **再读轻量化模型：** 理解模型优化方法；
5. **最后读星载人工智能与边缘部署：** 把算法研究和硬件实验连接起来。

阅读过程中可以交叉阅读，不必等一个类别全部读完才进入下一个类别。遇到与当前论文直接相关的基础论文，可以提前补读。

### 5.2 每天一篇论文的阅读节奏

每天尽量阅读一篇，但根据论文重要性采用不同深度：

- **快速浏览：** 先看标题、摘要、引言、图表和结论，判断是否与课题相关；
- **重点研读：** 对核心论文深入阅读方法、公式、实验设置和结果；
- **补充阅读：** 对背景相关但暂时不直接使用的论文，先记录核心观点和引用线索。

不要求每天都完全读懂一篇高难度论文。遇到关键公式或方法时，应留出时间查阅基础资料和复现思路。

### 5.3 每篇论文必须回答的问题

每篇论文的独立笔记至少回答：

1. 这篇论文的基本信息是什么？
2. 论文研究的具体问题是什么？
3. 为什么要研究这个问题？
4. 使用了什么数据集，数据和任务有什么特点？
5. 提出了什么方法，核心思想是什么？
6. 方法中的关键模块或公式分别起什么作用？
7. 实验如何设计，使用了哪些对比方法和评价指标？
8. 实验结果说明了什么，作者得出了什么结论？
9. 论文有哪些局限性或尚未解决的问题？
10. 这篇论文对我的研究有什么启发？下一步可以做什么？

每篇论文的详细笔记单独保存，不要把所有论文的内容都写进本 README。

## 9. 研究过程管理原则

1. **README 与论文笔记分开：** README 记录整个文献研究项目的方向和组织方式；每篇论文的具体内容单独记录。
2. **先理解，再复现，再改进：** 不在没有基线实验的情况下直接宣称提出创新方法。
3. **以研究问题组织阅读：** 阅读论文时关注它解决的问题和证据，而不是只记录模型名称。
4. **记录实验依据：** 数据划分、代码版本、参数、随机种子和评价指标尽量完整保存。
5. **避免数据泄漏：** 时间序列任务应谨慎设计训练、验证和测试划分。
6. **重视硬件指标：** 除检测精度外，还应关注推理延迟、内存、CPU 使用率和功耗。
7. **每周总结：** 记录本周读了哪些论文、学到了什么、完成了什么代码或实验、遇到什么问题以及下周计划。
8. **动态调整方向：** 如果文献和实验表明当前问题不适合，应根据证据调整研究切入点，而不是为了坚持最初设想而忽略结果。
